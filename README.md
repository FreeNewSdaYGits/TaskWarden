# Мост ntfy → Apprise → Telegram

Задача по расписанию публикует отчёт о пропущенных звонках в тему ntfy
`vats733614-01864742088727`. Этот мост слушает тему и пересылает каждое
сообщение в Telegram через Apprise. Полная таблица при этом по-прежнему
приходит в чат Алисы, а приложение ntfy на телефоне продолжает работать.

## Что понадобится

Хост, который постоянно работает и имеет доступ к `api.telegram.org`:
облачный сервис вроде Amvera, офисный компьютер, домашний сервер или VPS.
Из среды Алисы Telegram недоступен, поэтому мост запускается у вас.

Сам бот создаётся в Telegram — на хостинге живёт только его код.

## Шаг 1. Создать бота

1. В Telegram напишите @BotFather команду `/newbot`, задайте имя и получите
   токен вида `123456789:AAE...`.
2. Добавьте бота участником в группу с сотрудниками. Отдельно включать
   чтение сообщений не нужно: бот только отправляет, поэтому режим
   приватности можно не трогать.
3. Проверьте, что бот не ограничен в правах: в группе он должен иметь
   возможность отправлять сообщения (в обычной группе это право есть
   по умолчанию, в супергруппе с ограничениями его выдаёт администратор).

## Шаг 2. Узнать chat_id группы

1. Сразу после добавления бота откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`.
2. Найдите событие `"my_chat_member"` — в нём будет `"chat":{"id":-100...}`.
   Это и есть идентификатор группы; у групп он отрицательный.
3. Если список пуст, отправьте в группе команду `/start@<имя_вашего_бота>`
   и обновите страницу. Команды доходят до бота даже при включённом
   режиме приватности.

Для личного чата всё так же, только id будет положительным: напишите боту
любое сообщение и возьмите `chat.id` из `getUpdates`.

## Шаг 3. Заполнить настройки

Нужны три переменные:

| Переменная | Значение |
|---|---|
| `NTFY_TOPIC` | `vats733614-01864742088727` |
| `NTFY_SERVER` | `https://ntfy.sh` |
| `APPRISE_URLS` | `tgram://<токен>/<-100...>` — id группы |

Группа и личный чат одновременно — двумя адресами через пробел:

```
APPRISE_URLS=tgram://123456789:AAE.../-1001234567890 tgram://123456789:AAE.../987654321
```

Несколько разных каналов — через пробел:

```
APPRISE_URLS=tgram://123456789:AAE.../987654321 mailto://user:app-password@gmail.com
```

## Вариант A. Amvera

На Amvera контейнер не обязан принимать входящие соединения, так что
фоновый мост подходит без доработок: порт и health-check не нужны.

1. Создайте проект типа «Приложение» с окружением Docker.
2. Подключите Git-репозиторий, в котором лежат `Dockerfile`,
   `ntfy_to_apprise.py` и `amvera.yml` из этой папки.
3. В настройках проекта откройте раздел переменных окружения и добавьте
   `NTFY_TOPIC`, `NTFY_SERVER`, `APPRISE_URLS`. Файл `.env` на Amvera
   не нужен — переменные задаются в интерфейсе.
4. Запустите сборку. Дальше каждый `git push` пересобирает контейнер.
5. Логи смотрите в интерфейсе проекта. При старте там будет две строки:

```
канал подключён: tgram
Telegram API доступен (HTTP 200)
слушаю тему vats733614-01864742088727 на https://ntfy.sh
```

Если вместо второй строки появится «ВНИМАНИЕ: Telegram API недоступен»,
значит с площадки нет доступа к Telegram — тогда мост нужно переносить
на другой хостинг.

Файл `docker-compose.yml` для Amvera не используется: этот сервис
собирает проект по `Dockerfile`.

## Вариант B. Свой сервер с Docker

Скопируйте `.env.example` в `.env` рядом с `docker-compose.yml`, впишите
свои значения и запустите:

```bash
docker compose up -d --build
docker compose logs -f
```

## Шаг 4. Проверить доставку

Попросите отправить тестовое сообщение — оно должно прийти в Telegram
в течение нескольких секунд. Если сообщение есть в ntfy, но не в Telegram,
смотрите лог: там будет строка `ОШИБКА доставки` или предупреждение
о недоступности Telegram API.

## Как это работает

| Шаг | Что происходит |
|---|---|
| Задача Алисы | раз в час формирует список и публикует его в тему ntfy |
| Мост | держит потоковую подписку на тему и получает сообщение |
| Apprise | рассылает заголовок и текст во все каналы из `APPRISE_URLS` |
| Telegram | приходит сообщение от вашего бота |

Мост запоминает идентификаторы сообщений и время последнего полученного,
поэтому при обрыве связи не дублирует уже пересланное.

## Ограничения

- ntfy принимает сообщения до 4 КБ, Telegram — до 4096 символов. Список
  ограничен 40 строками, так что в лимит укладывается с запасом.
- Если контейнер остановлен, сообщения не теряются: при запуске мост
  продолжит с текущего момента, но пропущенное за время простоя
  в Telegram не придёт. История остаётся в ntfy и в чате Алисы.
- Тема ntfy публичная. Токен бота хранится в переменных окружения —
  не выкладывайте его в репозиторий и не пересылайте в переписке.
